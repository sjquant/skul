# Gitに変更を残さない仕組み

Skulはファイルを作成するときに、`.gitignore`やGitの履歴、インデックスを変更しません。これを実現するのが、次の3つの仕組みです。

## キャッシュとレジストリ {/* #the-cache-and-the-registry */}

| パス | 保存する内容 |
|---|---|
| `~/.skul/library/` | すべてのプロジェクトで再利用するバンドルのクローン |
| `~/.skul/registry.json` | 各リポジトリに**適用したい構成**と、各ワークツリーに**実際に書き込んだ内容** |

適用したい構成と実際の書き込み状態は、別々に記録します。新しくリンクしたワークツリーは適用したい構成をすぐに引き継ぎ、`skul apply`を実行するとファイルが書き込まれます。

## `.gitignore`ではなくローカルの除外ルール {/* #exclude-not-ignore */}

Skulが作成するファイルは、`.git/info/exclude`に登録します。このルールはローカルのクローンだけに適用され、コミットもプッシュもしません。バンドルを削除すると、登録した項目も削除されます。

Skulは書き込んだすべてのファイルのフィンガープリントも記録します。管理対象のファイルを編集した場合は、削除前に確認を求めます。`SKUL_NO_TUI=1`の場合は処理を拒否し、編集内容を無断で失わないようにします。

## ルートの指示ファイル {/* #root-instructions */}

`AGENTS.md`、`CLAUDE.md`、`QWEN.md`には別の扱いが必要です。チームがすでにこれらのファイルをコミットしている可能性があるためです。

:::note[Gitがファイルを追跡している場合]
自分の指示をローカルだけに適用するには、次の3点を守ってください。

- 変更を取り込むときは`skul sync`を使います。それ以外の`HEAD`を移動するGitコマンドは、実行前に`skul shadow --suspend`でシャドウを中断し、実行後に同じコマンドの`--refresh`で再適用します。
- Skulが管理している間は、ファイルを直接編集しないでください。
- 追跡中のファイルのシャドウを所有できるバンドルは、一度に1つだけです。
:::

### Gitが追跡していない場合 {/* #not-tracked */}

Skulはほかのファイルと同様にファイルを書き込み、Gitから隠します。ローカルにファイルがすでにあれば、その内容を元の状態として保存し、`SKUL:BUNDLE`マーカーで区切ってバンドルの内容を追記します。複数のバンドルで1つのファイルを共有でき、最後のバンドルを削除すると元のファイルに戻ります。

追記ではなく内容を置き換える場合は、`--root-instruction-mode replace`を使います。この場合も、バンドルを削除すると元の内容が復元されます。

### Gitが追跡している場合：シャドウ {/* #tracked-the-shadow */}

Gitがすでに追跡しているファイルの差分は、除外ルールでは隠せません。そこでSkulは、`HEAD`の内容に自分の指示を重ねたファイルを作業ディレクトリに書き込み、`skip-worktree`を設定します。`git status`には変更が表示されず、`skul status`では**シャドウ適用中の指示（Shadowed Instructions）**として表示されます。

追跡中のファイルのシャドウを所有できるバンドルは、一度に1つだけです。Skulは書き込んだファイルを生成物として扱うため、直接編集しないでください。Skulが書き込んだ内容と異なる場合、その後のコマンドは上書きを拒否します。

#### アップストリームの変更を取り込む {/* #pulling-upstream-changes */}

`skip-worktree`はアップストリームの変更も隠します。そのため、`HEAD`を移動する操作の前後でシャドウを中断し、再適用する必要があります。

```bash
skul sync
```

このコマンドはシャドウを中断し、`git pull --ff-only`を実行してから再適用します。pullに失敗した場合も、先にシャドウを復元します。アップストリームでファイルの追跡が終了していれば、そのシャドウを解除します。

ほかのGitコマンドは、同じ手順を手動で行います。

```bash
skul shadow --suspend
git rebase origin/main
skul shadow --refresh
```

ファイルにステージ済み、未ステージ、または未解決のマージによる変更がある場合、Skulはシャドウの作成や更新を拒否します。

## 後片付け {/* #cleaning-up */}

```bash
skul reset
```

このワークツリーでSkulが管理するものをすべて削除します。シャドウを適用したファイルは`HEAD`の内容に戻し、保存していたローカルの元ファイルも復元します。`git worktree remove`の前に実行してください。実行しないと、存在しなくなったクローンの記録がレジストリに残ります。
