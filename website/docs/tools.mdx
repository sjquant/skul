Grok Build and Kimi Code CLI expose skills as slash commands, so put those in `skills/`.

## Root instruction files

| File | Read by |
|---|---|
| `CLAUDE.md` | Claude Code |
| `AGENTS.md` | Cursor, Codex, OpenCode, Copilot, Kiro, Antigravity, Grok Build, Cline, Kimi Code CLI, ZCode |
| `QWEN.md` | Qwen Code |
| `.github/copilot-instructions.md` | Copilot |

A bundle only needs to ship one. Skul reuses the body for the others as long as it works unchanged.

## Global installs

`--global` writes under `~` instead of the project. Most tools use the same relative paths. The exceptions:

| Tool | Global locations |
|---|---|
| Antigravity CLI | `~/.gemini/antigravity-cli/skills`, `~/.gemini/config/agents`, `~/.gemini/GEMINI.md` |
| Cline | `~/.agents/AGENTS.md`; MCP in `~/.cline/data/settings/cline_mcp_settings.json` |
| Kimi Code CLI | `~/.kimi-code/skills`, `~/.kimi-code/agents`, `~/.kimi-code/AGENTS.md` |
| ZCode | `~/.zcode/skills`, `~/.zcode/commands`, `~/.zcode/AGENTS.md` (no subagents: its docs make them user-scope only) |

## Copilot

`copilot` means the Copilot CLI and the Agent Host behind it. Its repository files are also read by Copilot in VS Code, which reads `~/.copilot/skills` too, so one install serves both. Skul doesn't write `.vscode/mcp.json`: that's VS Code chat's own file, in another dialect.

## MCP dialects

Skul translates one `mcp.json` into each tool's spelling: `streamable-http` becomes `http` for Claude Code and Copilot, Copilot calls stdio servers `local`, Cursor and Kiro infer transport from `url`, Antigravity names the endpoint `serverUrl`, OpenCode folds `command` and `args` into one array, and Codex and Grok Build use TOML tables. See [Writing a bundle](/docs/bundles#mcp-servers).
