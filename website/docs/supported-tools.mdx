# Supported Tools

`skul` understands the directory layouts for these AI coding tools.

| Tool | Skills | Commands | Agents | Root instructions |
| --- | --- | --- | --- | --- |
| [Claude Code](https://docs.anthropic.com/en/docs/claude-code) | `.claude/skills` | `.claude/commands` | `.claude/agents` | `CLAUDE.md` |
| [Cursor](https://cursor.sh) | `.cursor/skills` | `.cursor/commands` | `.cursor/agents` | `AGENTS.md` |
| [OpenCode](https://opencode.ai) | `.opencode/skills` | `.opencode/commands` | `.opencode/agents` | `AGENTS.md` |
| [Codex](https://openai.com/index/openai-codex) | `.agents/skills` | - | `.codex/agents` | `AGENTS.md` |
| [GitHub Copilot](https://github.com/features/copilot) | `.github/skills` | - | `.github/agents` | `.github/copilot-instructions.md` |
| [Kiro](https://kiro.dev) | `.kiro/skills` | - | `.kiro/agents` | `AGENTS.md` |
| [Antigravity CLI](https://antigravity.google/) | `.agents/skills` | `.agent/workflows` | `.agents/agents` | `AGENTS.md` |
| [Grok Build](https://docs.x.ai/build/overview) | `.grok/skills` | `.grok/commands` | `.grok/agents` | `AGENTS.md` |
| [Qwen Code](https://qwenlm.github.io/qwen-code-docs/) | `.qwen/skills` | `.qwen/commands` | `.qwen/agents` | `QWEN.md` |

| [ZCode](https://zcode.z.ai/en/docs/welcome) | `.zcode/skills` | `.zcode/commands` | - | `AGENTS.md` |

Root instruction bundles are translated into the native root-instruction target for each selected tool.

For global Antigravity CLI materialization, Skul uses `~/.gemini/antigravity-cli/skills`, `~/.gemini/config/agents`, and `~/.gemini/GEMINI.md`.

`--agent` names a coding tool. DeepSeek provides models used through tools such as [Codex](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/) and [OpenCode](https://api-docs.deepseek.com/quick_start/agent_integrations/opencode/); use those tool names when targeting a DeepSeek-backed setup.

ZCode is a separate coding tool. Select it with `--agent zcode`. Skul currently targets its skills, commands, and root instructions; ZCode subagents are user-scope only, and its MCP configuration uses a nested format that Skul does not write.

## Target one tool or many

By default, canonical bundle content is copied into every compatible tool target.

Use `--agent` to constrain materialization:

```bash
skul add acme/shared-bundles core --agent codex
skul add acme/shared-bundles core --agent codex --agent cursor
```

This is useful when a bundle should only appear in a subset of tools for a repository.

## Tracked vs untracked root targets

If the destination root instruction file is untracked, `skul` composes it locally and hides it through `.git/info/exclude`.

If the destination root instruction file is already tracked, `skul` switches to tracked-shadow behavior so the effective file content can be refreshed from `HEAD` plus bundle overlays without creating a normal working-tree diff.
